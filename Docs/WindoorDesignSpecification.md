# Windoor UI・UXデザインガイド

このガイドはWindoor固有の機能仕様ではなく、設定画面とメニューバーの見た目・操作感を別のmacOSアプリへ流用するための資料です。数値と再利用部品は `Windoor/WindoorDesignSystem.swift` にまとめています。移植先では機能名や設定項目を差し替え、ここに記載した視覚階層とシステムUXを維持します。

## 1. デザイン原則

- macOS標準のウィンドウ、メニュー、スイッチ、チェックボックス、Picker、Sliderを基礎にする。
- 独自性はカード、角丸アイコン、アクセント色、余白のリズムで出す。
- 固定の白・黒背景は使わず、システムセマンティックカラーでライト／ダークモードへ追従する。
- 重要な操作は色だけに依存せず、ラベル、アイコン、無効状態、確認ダイアログでも伝える。
- 設定は1画面で俯瞰でき、縦に増えた場合は中央領域だけをスクロールさせる。

## 2. デザイントークン

| 用途 | 値 |
| --- | ---: |
| 設定ウィンドウ幅 | 440pt |
| 設定ウィンドウ高さ | 720pt |
| ページ余白 | 20pt |
| カード間隔 | 24pt |
| カードヘッダー余白 | 12pt |
| カード本文余白 | 16pt |
| カード角丸 | 12pt |
| カード境界線 | 1pt |
| アイコンバッジ | 28×28pt |
| アイコン角丸 | 6pt |
| 左ラベル列 | 110pt |
| 右コントロール列 | 150pt |
| メニュー項目アイコン | 16×16pt |

カードの影は黒5%、半径2pt、X方向0、Y方向1pt。数値を変更する場合は各Viewへ直接書かず、`WindoorDesign` のトークンだけを変更します。

## 3. 色とマテリアル

- ウィンドウとフッター: `windowBackgroundColor`
- カード: `controlBackgroundColor`
- カードヘッダー: `controlBackgroundColor` を50%の不透明度で重ねる
- 録画フィールド: `textBackgroundColor`
- 境界線と区切り: `separatorColor`
- 主テキスト: `.primary`
- 補助説明と無効ラベル: `.secondary`
- 言語／グローバル設定の代表色: 緑
- 情報・移動系の代表色: 青
- サイズ・注意喚起系の代表色: オレンジ
- 詳細／ツール系の代表色: 灰色
- 破壊的操作: 赤

アクセント色は意味に合わせて差し替え可能ですが、同じ画面内では「機能カテゴリ」と「色」を一対一に保ちます。

## 4. 設定ウィンドウの構造

設定ウィンドウは次の3層で構成します。

1. 上端の1pt区切り線
2. 設定カードを並べるスクロール領域
3. 再起動・終了などを置く固定フッター

ウィンドウには用途が分かるタイトルを設定します。表示言語や対象プロファイルが変わった場合はタイトルも同期して更新します。設定ウィンドウは閉じても参照を保持し、次に開いたとき同じウィンドウを前面へ戻すと、状態やスクロール位置を失いにくくなります。

## 5. カードコンポーネント

### スイッチ付きカード

ヘッダーは左から「角丸アイコン」「見出し」「可変スペース」「標準スイッチ」です。本文との間に区切り線を置きます。

- オン: カテゴリ色のアイコン、主テキスト、本文100%
- オフ: 灰色アイコン、二次テキスト、本文50%
- 前提設定が未登録: スイッチをオフかつ操作不能にする一方、登録用コントロールは操作可能にする

最後の状態は、必要情報がないまま機能だけが有効になる事故と、登録欄まで無効になって復旧できない行き止まりを同時に防ぎます。

### 詳細カード

スイッチを持たないカードです。アイコン、見出し、区切り線、本文の順で構成し、関連する補助設定をセクションとDividerで整理します。

### アイコンバッジ

`WindoorIconBadge(systemName:color:)` を使用します。SF Symbolsは白、背景はカテゴリ色、全体は28×28pt・角丸6ptです。別アプリではシンボル名と色だけを差し替えます。

## 6. 設定行の配置

- 行は左に `Label`、右にコントロールを置く。
- 左列は110ptで揃え、行が変わってもアイコンとラベルの開始位置を維持する。
- 右列は150pt。Picker、録画ボタン、値表示の幅を揃える。
- 補足文は対象コントロールの直下に `.caption` と `.secondary` で置く。
- 関係の深い複数設定は10〜16pt間隔、意味が変わる場所にはDividerを置く。
- 対になる設定は同じ行構造とアイコンの向きで表現する。例として、横方向は `arrow.left.and.right`、縦方向は `arrow.up.and.down` を使う。

## 7. キー録画UX

キー録画は他アプリへそのまま移植できるシステムUX部品です。

- 通常時は割当済みキーを表示し、空なら二次色で「未設定」と表示する。
- 録画中は赤い `record.circle.fill` をパルス表示する。
- フィールドは幅150pt、`textBackgroundColor`、角丸6pt、1pt境界線。
- 境界線は通常 `separatorColor`、録画中は青、競合時は赤。
- 修飾キーだけを記録するモードでは、長押しの進捗を青20%の面として左から右へ表示する。
- 長押し時間は0.5〜3.0秒、0.1秒刻み、既定1.5秒。
- 通常キーを含むモードではキー入力時に即時確定する。
- Escapeは録画を終了する。
- 同じ用途で両立しない割当が重複した場合は、赤い警告ラベルを録画欄の上に表示する。
- 修飾キーも指定キーもない割当は実行トリガーとして登録せず、対応する機能スイッチを自動的にオフにする。

録画ボタンと「修飾キーのみ」チェックボックスは右列で縦に積みます。複数のキー設定を並べる場合も同じコンポーネントを再利用します。

## 8. トグル、チェックボックス、Picker

- 機能全体の有効／無効にはヘッダー右の `.switch` を使う。
- 補助設定やシステム設定には本文内の `.checkbox` を使う。
- 列挙値はラベルを別に置き、Picker自体は `.labelsHidden()` として幅150ptへ揃える。
- 無効状態でも、再び有効化するために必要な入力だけは操作可能にする。
- Sliderには右側へ現在値を固定幅で表示し、ドラッグ中もレイアウトが動かないようにする。

## 9. メニューバーUI

- ステータスアイコンはアプリの主要概念を表すSF Symbolを1つ使い、テンプレート画像として明暗へ追従させる。
- メニューは「設定を開く」「再起動などの保守操作」「区切り線」「終了」の順にする。
- 設定項目は `⌘,`、再起動は `⌘R`、終了は `⌘Q` を基本とする。
- 再起動は `arrow.clockwise`、終了は `power` の16×16ptテンプレートアイコン。
- メニューラベルは短くし、表示言語が変わったらメニューを組み直す。

アプリ固有のクイック操作を追加する場合も、設定と終了の位置は安定させ、破壊的操作の直前に区切り線を置きます。

## 10. システムUX

### 言語とウィンドウタイトル

選択言語は永続化し、設定画面のラベル、ウィンドウタイトル、メニューバー項目を同時に更新します。システム追従を用意し、未対応言語では英語へフォールバックします。

### ログイン時に自動起動

macOS 13以降は `SMAppService.mainApp` を使います。チェックボックスの状態、保存値、システムの登録状態を同期し、登録失敗時はログへ残します。

### 再起動

現在の `Bundle.main.bundlePath` を `NSWorkspace.OpenConfiguration` で新しいインスタンスとして開き、その後に現在プロセスを終了します。設定画面フッターとメニューバーの両方から同じ処理を呼びます。

### 終了

メニューバーからは即時終了、設定画面からは確認ダイアログを表示します。設定画面の終了ラベルは赤、ダイアログは破壊的ボタンとキャンセルボタンを持ちます。

### 固定フッター

上端に1ptの区切り線、左右20pt・上下12ptの余白を取り、ボタンは右寄せにします。通常操作を先、破壊的操作を最後に置きます。

## 11. 再利用するコード

- `WindoorDesignSystem.swift`: 寸法、色、カード、アイコンのトークン
- `SettingsView.swift` の `SettingCard`: 有効スイッチ付きカード
- `SettingsView.swift` の `DetailSettingCard`: 補助設定カード
- `SettingsView.swift` の `KeyRecorderButton`: キー録画と進捗表示
- `WindoorApp.swift`: メニューバー、設定ウィンドウ、タイトル更新の接続例
- `LoginItemManager.swift`: ログイン起動
- `AppRestartManager.swift`: 再起動

移植時は、最初にトークンと共通Viewをコピーし、その後で色、SF Symbol、ラベル、保存モデルを対象アプリ用に差し替えます。カードの余白や列幅を各画面へ複製しないことが、見た目を長期的に揃えるポイントです。
